## Software used for the reported results

MATLAB R2026a Update 5 with the Statistics and Machine Learning Toolbox 26.1 (MathWorks, Natick, MA). The Optimization Toolbox 26.1 (`fminunc`) is used for the ordinal mixed model when present (as in the reported run); otherwise the script falls back to `fminsearch`. Random-number seed: 20260925 (set once at the start and again at the start of every cross-validation fold as `seed + 100 × strategy + fold`). Run time of the reported run (script v2.1, serial): 17 min (MATLAB Online).

Script versions: v2.1 (26 Sep 2026) produced the reported results. v2.2 (28 Sep 2026) adds Section 8c (distance of every misclassified session from the nearest cut point, computed from the Section 8 predictions), a completeness diagnostic in the log, and renames the continuous-prediction figure `Figure6_…` (it was `FigureS6_…`). v2.3 (29 Sep 2026) adds: Section 3b (cut points recomputed with each athlete omitted); a product-only model in Section 6; Section 8d (cluster bootstrap over training days and over athletes, and cluster-level sign-flip tests, for every pairwise accuracy difference; seeded separately with `cfg.seed + 777`); Section 8e (MRMR repeated on every inner training split); Section 8f (ordinal model with all six candidate predictors under LOAO); Section 8g (leave-one-day-out evaluation of the four deterministic models); a check that the PLI = 0 rows have non-zero sRPE, heart rate and distance; and, in Section 9a, an explicitly maximised fit of the non-parallel-slopes cumulative-logit model for the proportional-odds test with a convergence check (`cumlogitNPFit`), replacing `mnrfit`'s fit of that model, which stopped at its iteration limit (`mnrfit`'s statistic is still printed for comparison). None of these touches the random stream used in Section 8, so Tables 1–3 and S1–S9 are unchanged; the converged fit reproduced the proportional-odds statistic (LR = 8.36). The v2.3 run (1 Oct 2026, serial, 18.8 min) reproduced every v2.1 table byte for byte; its aggregate outputs are those in `results/`. v2.4 (3 Oct 2026) replaces that likelihood-ratio test by the Brant test (Section 9a; Table S12b): the non-parallel-slopes model gives negative fitted probabilities for 17 sessions, so a likelihood-ratio test against it is not valid; its fit is still printed, marked as information only. The Brant test's bootstrap draws from its own random stream (`RandStream('mt19937ar', 'Seed', cfg.seed)`), so no other output of v2.4 differs from v2.3. The reported Brant results were produced by `MSOC_brant_test.m`, which uses the same code and the same random stream.

## How to run the MATLAB script

1. Place `MSOC_ML_Pipeline.m` and `MSOC Data.xlsx` in the same folder. The workbook must contain the sheets `ML Sheet (2)` and `ALL POLAR DATA` with the columns listed in `DATA_DICTIONARY.md`, in the same row order (the script checks this). To test the script without the data, set `cfg.dataFile = 'MSOC_Data_SYNTHETIC.xlsx'`.
2. Optional dry run: set `cfg.quickTest = true` (12 tuning evaluations, primary strategy only; a few minutes). Do not report those numbers.
3. Set `cfg.quickTest = false` and run. Outputs are written to `MSOC_results/`.
4. `cfg.useParallel = true` uses the Parallel Computing Toolbox for the Bayesian optimization (3–4× faster) but is not bit-for-bit reproducible from the seed because parallel evaluations complete asynchronously. The reported run used `false`.

## Implementation notes

- **MRMR** is implemented explicitly (`mrmrMIQ`): relevance = mutual information between the discretized predictor and the PLI category; redundancy = mean mutual information with the predictors already selected; ranking by the mutual-information quotient (Ding & Peng 2005). Continuous predictors are cut into 10 equal-frequency bins whose edges are the (1..9)/10 quantiles of the data passed in (the training fold during cross-validation). Natural logarithms. MATLAB's `fscmrmr` was not used because its scores after the first predictor were numerically zero in these data, leaving the later ranks as arbitrary ties.
- **Hyperparameter search ranges** (standardized predictors): SVM box constraint C and kernel scale 10⁻³–10³ (log scale); AdaBoostM2 learning cycles 10–500, learning rate 10⁻³–1, maximum splits 1–20; SVR C and kernel scale as SVM, ε 10⁻³–10² robust SDs of z-scored PLI. Initial design: SVM C ∈ {0.1, 10, 1000} × kernel scale ∈ {0.3, 3, 30}; AdaBoostM2 cycles {30, 300} × rate {0.03, 0.3} × splits {2, 10}; SVR C {1, 100} × kernel scale {1, 10} × ε {0.01, 0.1} robust SDs. The configuration with the lowest observed inner error is refitted on all training sessions.
- **Ordinal mixed model** (`clmmFit`): cumulative-logit model with a random athlete intercept, maximum likelihood with 25-node Gauss–Hermite quadrature; marginal predictions for held-out athletes. Two built-in checks verify that, without the random effect, it reproduces `mnrfit` (difference in coefficients < 10⁻⁸; deviance identical).
- **Proportional-odds test** (Section 9a; `MSOC_brant_test.m`): Brant test (Brant R. Assessing proportionality in the proportional odds model for ordinal logistic regression. *Biometrics* 46: 1171–1178, 1990). A binary logistic regression is fitted at each cut point (PLI category > Low; > Medium) with the same z-scored predictors, and a Wald statistic, using Brant's covariance between the two sets of estimates, Cov(b_j, b_l) = (X'W_jj X)⁻¹ X'W_jl X (X'W_ll X)⁻¹ with W_jl = diag(π_l − π_j π_l) for l ≥ j, tests whether the slopes are equal: overall (df = 3) and for each predictor (df = 1). P-values are given from the χ² distribution and from a parametric bootstrap (2,000 data sets simulated from the fitted proportional-odds model), because with coefficients as large as these the Wald statistic was conservative at n = 372 in simulations (false-positive rate 2–3% at α = 0.05; 5% at n = 1,500 or with moderate coefficients). The test and its bootstrap treat athlete-sessions as independent (unlike the mixed models of Section 9, which include random effects); given the clustering by athlete and training day, it is reported as an exploratory diagnostic. The v2.3 likelihood-ratio test against the cumulative-logit model with separate slopes for each threshold (LR = 8.36) is not reported: that model, maximised to convergence (largest absolute gradient 2.6 × 10⁻⁶), gives negative fitted probabilities for at least one category in 17 sessions, so the likelihood-ratio statistic does not have its nominal distribution. Neither alternative is the multinomial (baseline-category) model that enters the cross-validated comparison as model (d).
- **Between-model comparisons** (Section 8d): the exact McNemar test treats sessions as independent pairs, which they are not (session ICC 0.53). The cluster bootstrap resamples whole clusters (training days, or athletes) with replacement and reports percentile 95% CIs for the difference in pooled accuracy; the sign-flip test permutes the sign of each cluster's difference in the number of correct classifications (exact enumeration of 2^10 patterns for athletes). Because bootstrap and Monte Carlo permutation values carry sampling noise at the second decimal, the manuscript and Supplemental Table S11 quote the confidence limits to one decimal (p-values: three decimals below 0.05, otherwise two).
- **Expected warnings** in the log: `AdaBoostM2 exits because pseudo-loss ... is not positive` (benign early stop of the ensemble); `mnrfit ... did not converge` (iteration limit) for `mnrfit`'s fit of the non-parallel-slopes model (no longer used for the reported statistic); and possibly `fitlme` or `mnrfit` messages in the leave-one-day-out folds (Section 8g) for days with very few sessions.

## Python implementation

`python msoc_pipeline.py --data "MSOC Data.xlsx"` writes the same CSV tables to `MSOC_results_python/` (`--quick` for a dry run: 12 tuning evaluations, primary strategy only, about 5 min) and a `software_versions.txt`. Requirements: Python ≥ 3.9, numpy, pandas, scipy, scikit-learn, statsmodels, scikit-optimize, openpyxl. Tested with Python 3.11.15, numpy 2.4.4, pandas 3.0.2, scipy 1.17.1, scikit-learn 1.8.0, statsmodels 0.15.0, scikit-optimize 0.10.2.

Status: the Python implementation has been run end to end on the simulated workbook (`python msoc_pipeline.py --data MSOC_Data_SYNTHETIC.xlsx --quick`, and in full two-strategy mode) and produces every table that the MATLAB script writes, including Sections 3b, 8b–8g and the standard errors of the ordinal and ordinal-mixed-model coefficients. It has not been run on the original data; the results reported in the manuscript are those of the MATLAB script, and numerical agreement between the two implementations on the study data has not been verified. The Python model column `AdaBoost_SAMME` corresponds to MATLAB's `AdaBoostM2` column. A defect in an earlier version of the Excel-time import (`to_minutes`, which applied the fraction-of-a-day factor to values already converted from time objects when a column's median was below one minute) was corrected on 29 Sep 2026; it affected only the Python zone-time import, never the MATLAB results.

All reported results were generated with MATLAB. The Python implementation was tested on the simulated workbook but has not been validated against the study data, so numerical equivalence between the implementations has not been established. The lists below record which components follow the same definitions as the MATLAB script and which use different algorithms or solvers:

- **Same definitions**: exclusion flow, cut points, descriptives, Spearman correlations (SciPy's p-values use the same t approximation as MATLAB for n > 10), repeated-measures correlations, construct R², MRMR ranking (`numpy.quantile(method='hazen')` reproduces MATLAB's `quantile`), ordinal and multinomial logistic regression (maximum likelihood; `statsmodels.OrderedModel` / `MNLogit`), the ordinal mixed model (same custom likelihood and quadrature), the linear mixed model (REML; `statsmodels.MixedLM`), all classification metrics, McNemar tests, the functional-form sensitivity (Section 8b) and the boundary distances (Section 8c).
- **Close but not identical**: SVM and SVR (scikit-learn's libsvm solver and MATLAB's SMO solver reach the same optimum up to tolerance; the kernel is mapped as gamma = 1/kernelScale²), and the Bayesian optimizer (scikit-optimize `gp_minimize` with expected improvement, MATLAB `bayesopt` with expected-improvement-plus). The same fixed initial design and ranges are used.
- **Proportional-odds test**: both scripts use the same Brant test (`brant_wald` / `brantWald`); the bootstrap p-values differ slightly because NumPy's and MATLAB's random streams differ (the Python `--quick` mode uses 200 bootstrap data sets).
- **Convergence note**: `statsmodels.MixedLM` may report `Converged: No` for the crossed athlete/session variance components (Section 9) even when the estimates are stable; compare the variance components with the MATLAB values in `results/Table_S14_LMM_variance_components.csv`.
- **Different algorithm**: MATLAB's `AdaBoostM2` (pseudo-loss boosting) has no scikit-learn equivalent; the Python script uses `AdaBoostClassifier` (SAMME) with depth-limited trees and labels the model `AdaBoost_SAMME` in every output. It is provided as an open-source alternative, not an exact reproduction.

## Testing the scripts without the data

`python make_synthetic_workbook.py` regenerates `MSOC_Data_SYNTHETIC.xlsx` (seeded; 26 athletes × 69 days, 11 primary athletes, one of them with a single complete session, three PLI = 0 artifact rows, 10 % missing wellness ratings, and a load score generated as duration × exp(0.07 × (%maxHR − 60)) with noise). Both scripts run on it unchanged. Its exclusion flow resembles the study's (1794 → 818 → 448/11 → 447/10 → 444/10 in the shipped file) but every value is simulated.
